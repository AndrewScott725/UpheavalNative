# Upheaval architecture refactor — 2026-09-27

This build keeps gameplay rules unchanged while moving high-churn responsibilities out of the three largest scripts.

## Simulation
- `sim/WallCombatSystem.gd`: perimeter geometry, wall contact, breach-entry geometry, combat activation.
- `sim/ArmySystem.gd`: strategic army survivor/return lifecycle helpers.
- `sim/BattleSnapshotSystem.gd`: battle serialization/activity helpers.
- `sim/RivalAISystem.gd`: difficulty pacing and AI target-selection policy.
- Existing `CombatSystem.gd`, `InvaderSystem.gd`, `RivalBattleSystem.gd`, and `FlowFieldRouter.gd` remain the specialized combat/movement systems.
- `UpMatch.gd` remains the authoritative coordinator and preserves its public API through thin delegates.

## Presentation
- `view/BoardCoordinates.gd`: camera, zoom/pan, board/grid projection, millimeter-to-pixel conversion and cell hit testing.
- Existing `ArmyRenderer.gd`, `CrowdPresentation.gd`, `CastleRenderer.gd`, `BuildingRenderer.gd`, `EffectsRenderer.gd`, `TooltipRenderer.gd`, and `CastleInteraction.gd` remain specialized presentation modules.
- `BoardView.gd` keeps stable wrapper methods so existing renderer and input code does not need call-site churn.

## Scenes
- `ui/BattlefieldRoot.tscn` owns the clipped battlefield and instanced `BoardView.tscn`.
- `ui/HUDRoot.tscn` owns dynamically-built HUD panels.
- `main.tscn` composes the battlefield and HUD roots instead of Main creating the board node at runtime.

## Safety goal
This was intentionally a behavior-preserving refactor. The current DINO-style packed crowd/ranged-wall fixes are retained. The next native crowd-solver integration can now target the crowd subsystem without coupling it to camera, HUD, AI policy, or perimeter geometry.
